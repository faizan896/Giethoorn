# 0021 — Declare one new reversal pilot and its lifecycle contract

Accepted, 28 November 2026 PKT; specification only, before implementation or data.

The accepted R002 diagnostic explains its incomplete exits and negative baseline
closes. Its explored source is not independent confirmation. Define
`r003-cost-reversion-001` under the [protocol](../r003-cost-reversion-plan.md) and
[constants](../r003-cost-reversion-policy.json), keeping all prior producers,
schemas, specifications, native image and historical results unchanged.

R003 tests a post-hoc 30-second-move reversal hypothesis over 120 seconds, with
a continuation control using the same new horizon and exits. This control avoids
crediting a direction change for an unmeasured exit/horizon change. Separate native
ledgers own each arm's quantities, fees, risks and assumed capacity. A causal
announced session budget and at most four settled residual closes handle planned
recording ends and partial/nonmarketable exits without forced liquidation.
Unexpected EOF, pending orders, risk halt and residual exposure remain failures
of complete economic coverage. Cross-recording persistent inventory is not added.

Old data is for software verification only. After tested software is frozen, bind
one new 64-attempt public-data cohort, resumable in batches of up to twelve within
seven days. Failed/interrupted slots are consumed, not replaced; economic readouts
wait for all slots. All 768 slots and fixed chronological thirds remain visible.
Positive baseline/stress/pair screens can propose only a separately declared later
confirmation cohort. Sparse/negative/incomplete results stop advancement.

Feature, exit, dataset-manifest and report namespaces start at version 1. This
decision authorizes no new live capability or existing schema change. The current
deliverable is the frozen reviewable specification, not a working R003 command,
new capture or trading result. The 24-hour and production gates remain open.
